# Valuation Vintage Policy

## 1. 이 파일이 고정하는 것

Valuation vintage는 **어떤 시점에 공개돼 있던 정보만으로 만든 가격·실적·전망의 한 묶음**이다. 나중에 공개된 자료를 과거 판단에 섞지 않아야 가치 변화와 정보 변화의 원인을 구분할 수 있다.

모든 모델과 보고서 첫 페이지에 `valuation_as_of`, `information_cutoff`, `last_actual_period`, `forecast_vintage`, `share_price_date`, `FX_date`, `model_version`을 기록한다.

## 2. 기본 날짜 규칙

| 항목 | 규칙 | 함께 기록할 내용 |
|---|---|---|
| 평가일 | 국내 주식시장 거래일 종가를 기본 사용 | 날짜, KRX 종가, 수정주가 여부, 데이터 URL |
| 정보 컷오프 | 평가일 장 마감까지 공개된 정보 | 실적 발표 시각이 장 마감 후라면 이후 거래일 가격을 새 vintage로 사용 |
| 최신 실제치 | 컷오프 시점까지 제출·발표된 가장 최근 분기/연간 수치 | 공시 접수일, 보고기간, 정정공시 여부, 연결/별도 여부 |
| 순현금·부채 | 최신 실제치의 보고기간 말 잔액 | 현금성자산, 단기·장기차입금, 리스부채 포함 여부, 환산 기준 |
| 주식수 | 평가일 현재 발행·희석 주식수 | 자사주, 전환증권, 잠재주식 처리 |
| 환율 | 평가일과 연결된 현물 기준 환율 | 통화쌍, 날짜, 출처 |
| 전망치 | 평가일 당시 공개됐던 회사 가이던스 또는 데이터 vintage | 하우스 추정/컨센서스 구분, 관측일, 제공자, 추정치 기간 |
| Peer 배수 | 같은 평가일의 주가·환율·주식수와 공개된 최신 실적 | TTM/NTM 정의, 회계연도 말, 순현금 기준일 |

평가일과 정보 컷오프가 다를 경우 둘 다 표기한다. 실적 발표 전날 주가와 발표 후 수정된 전망치를 하나의 스냅샷처럼 결합하지 않는다.

## 3. 정보 계층과 출처 기록

실제치 우선순위는 `DART 사업/반기/분기보고서 → 회사 공식 실적 발표자료 → 공식 컨퍼런스콜 → 신뢰 가능한 시장 데이터`다. 전망치는 `회사 가이던스 → 평가일 당시 컨센서스(라이선스 허용 시) → 분석가 추정` 순으로 분류한다.

각 입력 행에는 아래 필드를 기록한다.

`metric, value, unit, period_start, period_end, actual_or_estimate, publication_datetime, source_name, source_URL, retrieved_datetime, accounting_basis, consolidation_basis, model_cell, analyst_adjustment, confidence`

회사 자료가 범위 또는 방향만 제시하면 임의로 점 추정치로 바꾸지 않는다. 범위 그대로 저장하거나, 중간값을 쓴 경우 선택 이유와 민감도를 적는다.

## 4. HBM 세대별 vintage 정의

HBM vintage는 달력연도만으로 나누지 않는다. 세대별 제품은 아래의 **상업화 단계**에 놓고, 실제 증거에 따라 단계가 이동한다.

| 단계 | 단계 진입 증거 | Forecast에서의 처리 | 가치 반영 |
|---|---|---|---|
| 0. 개발·샘플 | 제품 발표, 샘플 제공, 설계/공정 개발 | 출하량을 확정하지 않음. 비용·일정 위험 표시 | Base 이익에 전량 반영하지 않고 Bull/옵션 시나리오로 분리 |
| 1. 고객 인증 | 고객 qualification 진행 또는 완료가 공식 확인 | 인증 고객·일정·품질 리스크를 별도 가정 | 승인 확인 전에는 양산 물량과 premium을 제한 |
| 2. 초기 양산 램프 | 공식 양산/출하 언급 또는 분기 매출에서 초기 기여 확인 | 공급량·수율·패키징 제약을 보수적으로 모델링 | ASP와 원가가 동시에 검증되지 않으면 세대 최고 마진 적용 금지 |
| 3. 수율·공급 안정 | 여러 기간의 출하 확대와 수율/원가 개선 증거 | 공급가능량을 수요와 구분하고 고객 집중 반영 | 이익·현금 기여가 확인된 만큼만 Base에 포함 |
| 4. 성숙·세대 전환 | 가격 하락, 차세대 migration 또는 제품 대체 확인 | ASP 하락과 신세대 전환 비용을 병행 | 고마진을 장기 terminal에 그대로 두지 않음 |

단계 변경은 `공시/IR 원문`, `발표 날짜`, `모델에서 바뀐 입력`, `이전 단계`, `변경 사유`가 있을 때만 한다. 언론 추정이나 제품 roadmap만으로 실제 수율·물량이 확정됐다고 처리하지 않는다.

### 세대별 수익 계산

가능한 범위에서 세대별 매출을 다음 항목으로 분해한다.

`출하 가능한 stack 수 = 투입 wafer × wafer당 gross die × wafer sort 수율 × 적층/패키징 수율 × 고객 인증/주문 제한`

`HBM 매출 = 출하 stack × ASP`

`HBM 영업이익 = 매출 - DRAM die 원가 - TSV/적층/패키징 원가 - 감가상각 배부 - 보증·초기 램프 비용`

공개되지 않는 wafer 투입, 수율, 고객별 ASP는 공개 사실이 아니라 analyst assumption으로 라벨링한다. 숫자 공개가 없으면 지수나 범위로 표현하고 정밀한 실제값처럼 보이는 수치를 넣지 않는다. HBM에 들어간 DRAM die를 범용 DRAM bit 출하에 중복 계상하지 않는다.

## 5. 실적/추정 vintage 이동 절차

1. 새 공시·실적발표의 접수/발표 시간과 정정 여부를 저장한다.
2. Actuals에 새 분기를 추가하고 전년 동기·직전 분기·누적치를 모두 대조한다. 누적 순이익을 단일 분기 수치로 오인하지 않는다.
3. 보고기간 말 현금·차입금·재고·CAPEX를 업데이트한다. 순현금은 정의와 부채 범위를 명시한다.
4. Forecast는 실제치로 바뀐 기간을 잠그고, 남은 연도의 수요·ASP·bit supply·마진 가정을 다시 설정한다.
5. HBM 세대별 상업화 단계와 고객/패키징 제약을 재판정한다.
6. SOTP·DCF·RIM·PER를 재계산하고, 가치 변화분을 `실적 반영`, `전망 변경`, `배수 변경`, `주식수/순현금 변경`으로 나눈다.
7. 새 vintage와 이전 vintage를 나란히 저장한다. 이전 스냅샷은 덮어쓰지 않는다.

## 6. Vintage 파일 이름과 변경 이력

- 데이터 스냅샷: `data/processed/YYYY-MM-DD_actuals_and_assumptions.csv`
- 분석 메모: `research/vintages/YYYY-MM-DD_vintage_note.md`
- 결과 표: 보고서에 평가일별 SOTP·DCF·RIM·PER와 주가를 함께 표기
- 변경 로그: 변경 셀/지표, 이전값, 새 값, 근거 URL, 작성일, 결과 영향

새 결과를 옛 평가일 이름으로 덮어쓰지 않는다. 소스가 정정되면 수정 전후 값과 정정일을 모두 기록한다.

## 7. 공시 없는 기간

새 분기/연간 실제치가 발표되지 않았다면 Actuals를 바꾸지 않는다. 가격·환율만 갱신한 경우 전체 모델을 새 평가일로 재작성했는지 분명하게 표시한다. 실적이 없는데 자동으로 새 목표가를 발표하지 않는다.
